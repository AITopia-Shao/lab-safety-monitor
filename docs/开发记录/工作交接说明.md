## 1. 项目是什么

**作品**：基于双摄协同的实验室安全事前干预监测系统（晋级标题："基于双目视觉与多源环境传感的高危实验室安全监测终端"）
**比赛**：2026 年（第 22 届）湖南省大学生计算机设计大赛，嵌入式开发赛道，约一周后路演，答辩 10 分钟。
**一句话**：两路摄像头（全景看人、台面看器皿）+ 环境传感器（温湿度、热源红外测温、烟雾），在香橙派上用 YOLO 实时识别违规和危险，分级干预（语音、三色灯、断电），下位机（ESP32-S3）负责独立的硬件安全兜底。

### 运行平台
- 上位机：**香橙派**（RK3588S 或 RK3576，待定），Ubuntu 22.04，Python 3.10，NPU 推理用 RKNN 格式
- 下位机：ESP32-S3-DevKitC-1，Arduino 框架
- 开发调试：Windows PC，可以不接任何硬件运行（自动进入模拟模式）

### 架构（四层，第二、三层未实现）
```
感知层  YOLO11（人员装备 12 类 + 器皿 14 类）+ SHT30 / MLX90614 / MQ-2       ← 已完成
预测层  热源温度趋势 → 预计多少秒后干烧（"世界模型思想"的轻量实现）       ← 待做
认知层  多模态大模型 Agent 复核 + RAG 引用安全手册 + 值守问答              ← 待做
执行层  状态机 8 条规则 + 断电锁定 + 下位机本地硬规则 / 看门狗             ← 已完成
```

## 3. 编码约定（所有执行者必须遵守）

1. **不改前端**：`src/ui/main_window.py` 一行都不改；需要界面配合的功能，先在后端做好，写明"待前端接入"。
2. **好改优先**：能小改就不重写；不改已有函数的签名和返回值（界面在调用它们）。
3. **参数进配置**：新的阈值、开关写进 `config.yaml`，同时在 `src/config.py` 的 `DEFAULTS` 里加默认值。
4. **Qt 导入写法**：先 `try: from PySide6...`，失败再 `from PyQt6...`（参考 `state_machine.py` 开头）。
5. **不阻塞界面线程**：网络请求、文件 IO、大模型调用一律放后台线程（参考 `events.py` 的 `_io_loop`）。
6. **串口只经过 `SerialComm`**：不要在别处 `serial.Serial(...)`。
7. **告警走事件中心**：持续性状态用 `events.update(kind, active, level, title, message)`；一次性记录用 `events.log(...)`。
8. **安全原则**：软件只能断电、不能上电；大模型的输出**只能作为建议，不能触发或取消断电**。
9. **如实描述**：日志和告警不能宣称没有发生的事（例如没收到 ACK，就不能写"已断电"）。
10. **注释和日志用中文**，风格参照现有文件。
11. **改完必须运行**：`python tests/test_backend.py`，全部通过才算完成；新功能要加对应的测试。
12. Windows 下注意：路径里有中文，读图片用 `cv2.imdecode(np.fromfile(...))`，写图片用 `cv2.imencode` 后 `open().write()`。

## 6. 不要交给便宜模型的事

- 认知层（Agent / RAG）：涉及线程模型、安全边界和提示词设计，需要整体判断。
- 前端优化：要同时理解界面结构和后端信号，改动面大。
- 修改串口协议或安全规则的阈值逻辑：一处改错，会导致断电失效或误断电。
- 真机联调排错：需要结合现象来推理。
