## 结论速览
真正的亮点只有一条主线：**热源测温 + 有没有人 → 开发板判断 → 下位机断电，现场复位，下位机还有独立兜底**。
其余功能多数是"加分装饰"，一部分会让评委觉得堆砌，还有几处逻辑经不起追问。

## 一、经不起追问的地方（必须改）
1. **"有没有人"靠装备模型推断**（`dual_inference.py` `_update_presence`）：模型没有 person 类。
   - 人背对镜头或站得远、模型没认出装备 → 误判无人 → R3 60 秒后断电，误断电。
   - 实验服挂在椅背上 → 一直算有人，该断时不断。
   - 而 R3 是会断电的规则。改法：加 COCO 预训练的 person 检测（不用自己标注），或加 LD2410 毫米波雷达，两者取"或"。
2. **120℃ 干烧阈值测的是什么表面？**（R1、固件 150℃）
   - 测加热片 / 电热板：正常工作就远超 120℃，会频繁误断电；"沸点平台"也不成立。
   - 测烧杯外壁：玻璃对红外不透明，读到的是外壁温度，平台假设才成立。
   - 必须在文档和装置上写死"测温头对准容器外壁"，并实测一组曲线证明。
3. **MQ-2 对酒精敏感**：实验室常用酒精灯、乙醇，可能触发 R5 烟雾断电；阈值 1800 / 2500 是原始 ADC 值，没有标定。需要实测"酒精挥发 / 打火机放气 / 真烟"三组读数再定阈值，否则就是拍脑袋。
4. **24W 加热片能否把水烧开要先算清楚**：12V 接 6Ω 只有 24W，50 mL 水升温 80℃ 约需 17 kJ，理想情况也要 12 分钟以上，加上散热可能根本烧不开。现场演示"沸腾 → 烧干 → 断电"可能做不出来。要么用很少量水，要么演示改为"空烧升温"。

## 二、实现了但意义不大（建议砍或降级）
| 功能 | 问题 | 建议 |
|---|---|---|
| 台面器皿识别（第二路摄像头 + chem 模型） | 只用在 R4（接了红外后永远不触发）和 R8（NOTICE 级）；`edge_risk` 是固定画线，很牵强 | 要么让它真正参与判断（如"加热中但台上无容器 = 空烧"、"红外测温点上有没有容器"），要么答辩少讲 |
| R4 兜底（环境 >55℃） | 室温到 55℃ 时早着火了，不会触发 | 删，或明确只用于"没装红外"的配置 |
| 外部温湿度控制（风扇 + 加湿片 + SET_ENV/SET_ACT 协议） | 化学实验台上放加湿器本身不合理；5V 小风扇不能代替通风橱；温湿度控制是空调的活 | 删加湿；风扇改成"烟雾时排风联动"一个动作即可 |
| R6 高湿、R7 环境高温 | 与"实验台安全"关系弱 | 保留为提示，不当亮点 |
| V-JEPA 2 异常检测 | 1.3GB 模型、要电脑端、效果未验证、只出提醒，属于堆热词 | 从答辩里去掉，代码可留 |
| 伏案睡觉、饮食、头罩、口罩 | 判断粗糙（头的高度 + 静止）；头罩、口罩不是化学实验通用要求，像是公开数据集自带的类别 | 只保留护目镜、实验服（手套可选），减少误报 |
| 电脑大窗口 `main_window.py`（1590 行） | 开发板上不用，和小屏、网页三套界面重复维护 | 冻结，答辩只讲小屏 + 网页 |
| 大模型看图（VL）、继续扩展安全助手 | 正好和网上成批出售的模板"撞脸" | 保持只读 + 规则模板兜底，一笔带过 |
